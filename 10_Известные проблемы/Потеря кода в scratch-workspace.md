# Потеря кода в scratch-workspace

**Приоритет:** CRITICAL  
**Статус:** Open  
**Создано:** 2026-07-30  
**Ответственный:** все профили (правило для команды)

## Описание проблемы

Kanban-диспетчер Hermes при завершении/очистке задачи удаляет scratch-воркспейс — временную директорию `C:\Users\user\AppData\Local\hermes\kanban\boards\hr-project\workspaces\t_<id>\`. Если разработчик не выполнил `git push` до того, как задача была заблокирована на review или завершена — **весь код в scratch-воркспейсе удаляется безвозвратно**.

Корневая причина: scratch-воркспейс — это изолированная песочница, не привязанная к git-репозиторию. В отличие от worktree, в scratch нет `.git`, нет связи с репозиторием, нет защиты от потери.

## Решение

### 1. Использовать git worktree вместо scratch

Для всех задач, связанных с кодом, использовать `workspace_kind: "worktree"` при создании задачи:

```
kanban_create(..., workspace_kind="worktree")
```

Worktree — это полноценная git-рабочая копия со своим `.git`, привязанная к репозиторию. Даже если worktree будет удалён, все закоммиченные изменения останутся в репозитории.

### 2. Обязательный push перед блокировкой на review

**Правило для всех программистов:** перед вызовом `kanban_block(reason="review-required: ...")` ОБЯЗАТЕЛЬНО выполнить:

```bash
git add -A
git commit -m "WIP: <описание> (pre-review)"
git push origin <branch-name>
```

Без этого правила задача уходит на review, scratch-воркспейс может быть очищен — и код потерян навсегда.

### 3. Санитарная проверка (checklist) перед block

Перед любой блокировкой задачи проверить:

- [ ] `git status` — нет незакоммиченных изменений
- [ ] `git log --oneline -3` — последние коммиты на месте
- [ ] `git push origin <branch>` — изменения ушли в remote
- [ ] Только после этого: `kanban_block(...)`

## Правило для всех профилей

> **Перед блокировкой задачи на review — всегда делай `git push`. Никаких исключений.**

Это правило внесено в [[AGENTS.md#правила-работы]] и является обязательным для `hr-backend-programmer`, `hr-frontend-programmer`, `hr-integration-devops`.
