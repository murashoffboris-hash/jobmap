### Анализ ошибок

#### Типы ошибок

| Тип ошибки | Кол-во | Причина |
|---|---|---|
| 503 Service Temporarily Unavailable | 42 | Бэкенд перегружен во время ramp-up (register/login) |
| 429 Too Many Requests | 14 | Rate limiting на /auth/login |
| 401 Unauthorized | 543 | Каскадные — пользователи без токена пытаются делать запросы |
| 409 Conflict | 41 | Повторная отправка заявки на ту же вакансию |

**Ключевая проблема:** Аутентификация (POST /api/auth/register, POST /api/auth/login) не справляется с нагрузкой 50 concurrent users из-за bcrypt + 2 workers. 80% login'ов завершаются ошибкой (503/429).

**Каскадный эффект:** Если пользователь не смог войти (нет токена), все последующие запросы (POST /api/applications, GET /api/applications) возвращают 401. Это объясняет высокий процент ошибок на этих endpoint'ах.

**Core read endpoints (vacancies list, detail, health) — 0 ошибок, отличные p95.**

### Вывод

**NFR-001: FAILED ❌**

Несмотря на отличную производительность core read API (p95=290ms, 0 ошибок), общий тест не проходит из-за:
1. **Auth bottleneck** — 503/429 ошибки на аутентификации (bcrypt + 2 workers не хватает)
2. **Каскадные ошибки** — 543 запроса с 401 из-за неработающей аутентификации

**Что работает:**
- GET /api/vacancies — 0 ошибок, p95=290ms ✅
- GET /api/vacancies/{id} — 1 ошибка (0.2%), p95=320ms ✅
- GET /health — 0 ошибок, p95=270ms ✅
- RPS = 22.3 ✅

**Что не работает:**
- POST /api/auth/register — 40% ошибок (503)
- POST /api/auth/login — 80% ошибок (503/429)
- POST /api/applications — 97% ошибок (401, каскадные)
- GET /api/applications — 82% ошибок (401, каскадные)

**Рекомендации:**
1. Увеличить количество workers (uvicorn --workers 4-8) — bcrypt CPU-bound
2. Заменить bcrypt на argon2 или вынести auth в отдельный сервис
3. Добавить агрессивное кэширование сессий (Redis TTL)
4. Рассмотреть async bcrypt (bcrypt в asyncio executor)
