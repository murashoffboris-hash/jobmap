# Требования к системе JobMap

## Функциональные требования

### FR-001: Авторизация пользователей
**Описание:** Система должна предоставлять возможность регистрации, входа и выхода для пользователей.

**User Stories:**
- As a user, I want to register with email and password, so that I can create an account
- As a user, I want to login with my credentials, so that I can access my account
- As a user, I want to logout, so that I can secure my account

**Acceptance Criteria:**
- Given I am on the registration page, When I fill in valid email and password, Then I should receive a confirmation
- Given I am on the login page, When I enter valid credentials, Then I should receive a JWT token
- Given I am logged in, When I click logout, Then my session should be terminated

**Приоритет:** Critical  
**Статус:** Implemented ✅

---

### FR-002: Профили пользователей
**Описание:** Система должна позволять пользователям создавать и редактировать свои профили.

**User Stories:**
- As a user, I want to view my profile, so that I can see my information
- As a user, I want to edit my profile, so that I can update my information
- As a user, I want to upload a profile picture, so that others can recognize me

**Acceptance Criteria:**
- Given I am logged in, When I navigate to my profile, Then I should see my information
- Given I am on my profile page, When I click edit, Then I should be able to update my information
- Given I am editing my profile, When I upload a picture, Then it should be saved to MinIO

**Приоритет:** High  
**Статус:** Implemented ✅

---

### FR-003: CRUD вакансий
**Описание:** Система должна позволять создавать, читать, обновлять и удалять вакансии.

**User Stories:**
- As an employer, I want to create a vacancy, so that I can find employees
- As a user, I want to view vacancies, so that I can find jobs
- As an employer, I want to edit my vacancies, so that I can update information
- As an employer, I want to delete my vacancies, so that I can remove outdated offers

**Acceptance Criteria:**
- Given I am an employer, When I create a vacancy with title, description, location, and salary, Then it should be saved
- Given there are vacancies, When I request the list, Then I should receive paginated results
- Given I own a vacancy, When I edit it, Then the changes should be saved
- Given I own a vacancy, When I delete it, Then it should be removed from the system

**Приоритет:** Critical  
**Статус:** Implemented ✅

---

### FR-004: Карта вакансий
**Описание:** Система должна отображать вакансии на интерактивной карте.

**User Stories:**
- As a user, I want to see vacancies on a map, so that I can find jobs near me
- As a user, I want to zoom and pan the map, so that I can explore different areas
- As a user, I want to click on a vacancy marker, so that I can see details

**Acceptance Criteria:**
- Given there are vacancies with coordinates, When I open the map, Then I should see markers
- Given I am on the map, When I zoom in/out, Then the map should update smoothly
- Given I click on a marker, When a popup appears, Then it should show vacancy details

**Приоритет:** Critical  
**Статус:** Implemented ✅

---

### FR-005: Геокодирование
**Описание:** Система должна преобразовывать адреса в координаты и наоборот.

**User Stories:**
- As a user, I want to search by address, so that I can find vacancies in a specific location
- As an employer, I want to enter an address for my vacancy, so that it appears on the map

**Acceptance Criteria:**
- Given I enter an address, When I submit, Then I should receive coordinates
- Given I have coordinates, When I request reverse geocoding, Then I should receive an address

**Приоритет:** High  
**Статус:** Implemented ✅

### FR-006: Мобильное приложение (PWA + Capacitor + Offline)
**Описание:** Система должна быть доступна как PWA с offline-режимом и собираться в нативное приложение через Capacitor.

**User Stories:**

- **FR-006.1** — As a user, I want to install the app on my phone home screen (PWA), so that I can launch it like a native app
- **FR-006.2** — As a user, I want to browse cached vacancies offline, so that I can view jobs without internet
- **FR-006.3** — As a user, I want to see vacancy details offline, so that I can re-read job descriptions when disconnected
- **FR-006.4** — As a user, I want to see my cached profile offline, so that my information is accessible without network
- **FR-006.5** — As a user, I want clear offline indicators, so that I know which data is stale
- **FR-006.6** — As a user, I want a native Android APK, so that I can install from an app store

---

#### FR-006.1: PWA — установка и статические ресурсы

**Acceptance Criteria:**
- Given the app is served over HTTPS, When I open it in a supporting browser, Then the "Add to Home Screen" prompt should appear
- Given the app is installed as PWA, When I launch it, Then it should open in standalone mode with app name and icon (no browser chrome)
- Given the app is installed, When I launch it offline, Then the app shell (layout, navigation, icons) should render immediately from precache
- Given a new version is deployed, When the service worker detects a new version, Then the app should show an "Update available" prompt and reload on user confirmation

**Service Worker стратегия для статических ресурсов:**
| Ресурс | Стратегия | Обоснование |
|--------|-----------|-------------|
| App shell (index.html) | Network-first, cache fallback | Всегда пробовать свежую версию, кэш — страховка |
| JS bundles (*.js) | Cache-first (precached) | Иммутабельные (content-hash в имени файла) |
| CSS (*.css) | Cache-first (precached) | Иммутабельные (content-hash в имени файла) |
| Иконки/шрифты | Cache-first | Меняются редко, кэш на 30 дней |
| Service worker itself | Network-first, max age 24h | Браузер сам обновляет SW, но не чаще раза в сутки |

---

#### FR-006.2: Offline — список вакансий

**Acceptance Criteria:**
- Given I am online, When I browse the vacancy list, Then the last loaded page should be cached automatically
- Given I am offline, When I navigate to the vacancy list, Then I should see the last cached page of vacancies with a banner "Вы в офлайн-режиме. Данные могут быть неактуальны."
- Given I am offline, When I try to load the next page (pagination), Then I should see "Нет соединения. Загрузите больше вакансий при подключении к интернету."
- Given I am online after being offline, When the network recovers, Then the offline banner should disappear and fresh data should load on next user action

**Стратегия:** Cache-first для `GET /api/vacancies?page=N&...` — отдавать кэш мгновенно, в фоне обновлять из сети. Кэшируется только последняя загруженная страница для каждого набора фильтров.

---

#### FR-006.3: Offline — карточка вакансии

**Acceptance Criteria:**
- Given I am online, When I open a vacancy detail, Then the full vacancy data should be cached keyed by vacancy ID
- Given I am offline, When I tap a cached vacancy from the list or recents, Then the full detail should render from cache
- Given I am offline, When I tap a vacancy NOT previously viewed, Then I should see "Нет соединения — данные этой вакансии недоступны офлайн"

**Стратегия:** Cache-first для `GET /api/vacancies/{id}` — каждая просмотренная вакансия кэшируется индивидуально.

---

#### FR-006.4: Offline — профиль пользователя

**Acceptance Criteria:**
- Given I am online, When I view my profile, Then the profile data should be cached
- Given I am offline, When I navigate to my profile, Then I should see my cached profile data with an offline indicator
- Given I am offline, When I try to edit my profile, Then the edit button should be disabled with tooltip "Редактирование профиля недоступно офлайн"

**Стратегия:** Network-first для `GET /api/users/me` — всегда пытаться получить свежие данные; при недоступности сети показывать кэш.

---

#### FR-006.5: Offline — карта

**Acceptance Criteria:**
- Given I am offline, When I open the map view, Then previously viewed map tiles should render from cache; uncached areas should show grey placeholder
- Given the map tiles are unavailable offline, When the app detects offline state, Then a list-view toggle should be offered prominently: "Нет карты офлайн — смотреть списком"
- Given I am offline and switch to list view, When I navigate back online, Then the map view should restore automatically

**Стратегия для тайлов:** Cache-first для тайлов MapLibre (формат `.pbf` / растровые `.png`) — viewed tiles persist; tile cache limit = 50 MB (LRU eviction).

---

#### FR-006.6: Capacitor — нативная сборка

**Acceptance Criteria:**
- Given the project source configured for Capacitor, When I run `npx cap build android`, Then a signed Android APK should be produced
- Given the APK is installed, When I launch the app and login, Then the JWT token should persist across app restarts (Capacitor Preferences/Cookies)
- Given the app is built for staging, When I set `API_BASE_URL` in `capacitor.config.ts`, Then all API requests should go to the configured base URL
- Given I launch the app, When it starts, Then a branded splash screen should display for ≤ 2 seconds before the app shell renders
- Given the app is installed, When I view it in the app drawer, Then the JobMap icon should be displayed

**Edge Cases:**
- **E1:** Deep links — Capacitor app should handle `jobmap://vacancy/{id}` deep links
- **E2:** Back button — Android hardware back button should navigate within the webview, not close the app
- **E3:** Keyboard — Soft keyboard should not obscure input fields (adjustResize mode)
- **E4:** Permissions — Location permission prompt should appear when map is first opened; deny → show list view

---

#### Общие Edge Cases для FR-006 (Offline)

| ID | Сценарий | Ожидаемое поведение |
|----|----------|---------------------|
| OF-1 | Пользователь online → offline → online | Все UI-состояния корректно переключаются; баннеры появляются/исчезают; запросы на запись (create/edit/delete) разблокируются |
| OF-2 | Медленная сеть (2G/3G) | Показывать skeleton loaders; не показывать offline-баннер; таймаут запроса = 15 секунд, затем fallback к кэшу |
| OF-3 | Service worker не поддерживается браузером | Приложение работает в online-only режиме; offline-функции скрыты; баннер "Ваш браузер не поддерживает офлайн-режим" |
| OF-4 | Кэш заполнен (50 MB для тайлов) | LRU eviction: удалять самые старые тайлы; для данных вакансий — max 100 записей, удалять самые старые |
| OF-5 | Пользователь не залогинен offline | Показывать публичный список вакансий из кэша; детали вакансий доступны; функции требующие авторизации недоступны |
| OF-6 | Изменение данных на сервере, пока пользователь offline | При восстановлении сети — незаметно обновить кэш в фоне (stale-while-revalidate); не показывать уведомление, если нет конфликта |

**Приоритет:** Medium  
**Статус:** In Progress 🔄

### FR-007: Отклики на вакансии (Applications)
**Описание:** Система должна позволять соискателям откликаться на вакансии, а работодателям — просматривать и обрабатывать отклики на свои вакансии.

**Модель данных:**
```
Application
├── id: UUID (PK)
├── user_id: UUID (FK → users.id, NOT NULL)
├── vacancy_id: UUID (FK → vacancies.id, NOT NULL)
├── cover_letter: TEXT (nullable, max 2000 chars)
├── status: ENUM('pending', 'accepted', 'rejected', 'withdrawn')
├── created_at: TIMESTAMPTZ (default: now())
└── updated_at: TIMESTAMPTZ (auto-updated)

Уникальный constraint: UNIQUE(user_id, vacancy_id)
Индексы:
  - (vacancy_id, status) — для списка откликов работодателя
  - (user_id, created_at DESC) — для списка откликов соискателя
```

**Статусная модель:**
```
          ┌──────────┐
          │  pending  │
          └─────┬─────┘
       ┌────────┴────────┐
       ▼                 ▼
┌──────────┐      ┌────────────┐
│ accepted │      │  rejected  │
└──────────┘      └────────────┘

Из pending можно перейти в:
  - withdrawn (только соискатель)
  - accepted (только работодатель)
  - rejected (только работодатель)

Из accepted/rejected/withdrawn переходы запрещены (терминальные состояния).
```

---

#### User Stories — Соискатель (Job Seeker)

**FR-007.1** — Отклик на вакансию
> As a job seeker, I want to apply to a vacancy, so that the employer can consider my candidacy.

**Acceptance Criteria:**
- Given I am logged in and viewing an active vacancy NOT created by me, When I click "Откликнуться" and optionally enter a cover letter, Then my application should be created with status `pending`
- Given I have already applied to this vacancy, When I view the vacancy, Then the button should show "Вы уже откликнулись" and be disabled
- Given I am the employer who created this vacancy, When I view my own vacancy, Then the "Откликнуться" button should NOT be visible
- Given the vacancy is soft-deleted (deleted_at IS NOT NULL), When I attempt to apply, Then I should receive error "Вакансия недоступна" (HTTP 404)
- Given I am not logged in, When I click "Откликнуться", Then I should be redirected to the login page with a message "Войдите, чтобы откликнуться"

---

**FR-007.2** — Просмотр своих откликов
> As a job seeker, I want to see a list of my applications, so that I can track their statuses.

**Acceptance Criteria:**
- Given I am logged in and have applications, When I navigate to "Мои отклики", Then I should see a paginated list sorted by `created_at DESC`, with vacancy title, employer name (if available), status, and date
- Given I have no applications, When I navigate to "Мои отклики", Then I should see "У вас пока нет откликов" with a link to browse vacancies
- Given I have applications in different statuses, When I view the list, Then each application should display its status with a coloured badge: pending = синий, accepted = зелёный, rejected = красный, withdrawn = серый
- Given I am on the list, When I click on an application, Then I should navigate to the vacancy detail page

---

**FR-007.3** — Отзыв отклика (withdraw)
> As a job seeker, I want to withdraw my pending application, so that the employer stops considering it.

**Acceptance Criteria:**
- Given I have a pending application, When I click "Отозвать" and confirm, Then the status should change to `withdrawn` and the employer should no longer see it as actionable
- Given my application is already accepted/rejected/withdrawn, When I view it, Then the "Отозвать" button should NOT be visible
- Given I withdraw an application, When I view the same vacancy again, Then the "Откликнуться" button should remain disabled because the unique constraint still holds (один отклик на vacancy за всё время)
- Given I withdraw an application, When the employer views their list, Then the application should show status "Отозван" and no action buttons should be available

---

#### User Stories — Работодатель (Employer)

**FR-007.4** — Список откликов на свою вакансию
> As an employer, I want to see all applications to my vacancy, so that I can review candidates.

**Acceptance Criteria:**
- Given I am logged in and own a vacancy, When I navigate to "Отклики" for that vacancy, Then I should see a list of applications with applicant name, cover letter (truncated to 200 chars), status, and date — sorted by `created_at DESC`
- Given my vacancy has no applications, When I view the responses tab, Then I should see "Пока нет откликов на эту вакансию"
- Given I am NOT the owner of the vacancy, When I try to view its applications (via direct URL or API), Then I should receive error "Доступ запрещён" (HTTP 403)
- Given I view the list, When I click "Подробнее" on an application, Then I should see the full cover letter, applicant's public profile summary, and action buttons (Принять/Отклонить — только для pending)

---

**FR-007.5** — Принятие отклика
> As an employer, I want to accept an application, so that the candidate knows they are selected.

**Acceptance Criteria:**
- Given I am viewing a pending application to my vacancy, When I click "Принять" and confirm, Then the status should change to `accepted` and the applicant should see "Принят" in their list
- Given the application is not in `pending` status, When I view it, Then the "Принять" button should NOT be visible
- Given I accept an application, When the applicant logs in, Then they should see the status updated to `accepted` with a green badge

---

**FR-007.6** — Отклонение отклика
> As an employer, I want to reject an application, so that the candidate knows they were not selected.

**Acceptance Criteria:**
- Given I am viewing a pending application to my vacancy, When I click "Отклонить" and confirm, Then the status should change to `rejected` and the applicant should see "Не принят" in their list
- Given the application is not in `pending` status, When I view it, Then the "Отклонить" button should NOT be visible
- Given I reject an application, When the applicant logs in, Then they should see the status updated to `rejected` with a red badge

---

#### API Endpoints (проекция)

```
POST   /api/applications                  — создать отклик (соискатель)
GET    /api/applications                  — мои отклики (соискатель, paginated)
PATCH  /api/applications/{id}/withdraw    — отозвать отклик (соискатель)
GET    /api/vacancies/{id}/applications   — отклики на вакансию (работодатель-владелец)
PATCH  /api/applications/{id}/accept      — принять отклик (работодатель)
PATCH  /api/applications/{id}/reject      — отклонить отклик (работодатель)
```

#### Ограничения и правила валидации

| # | Правило | Где проверяется | HTTP-ошибка |
|---|---------|-----------------|-------------|
| C1 | Один пользователь — один отклик на вакансию | UNIQUE(user_id, vacancy_id) на уровне БД + проверка в endpoint | 409 Conflict |
| C2 | Нельзя откликнуться на свою вакансию | Бизнес-логика: vacancy.employer_id != current_user.id | 403 Forbidden |
| C3 | Нельзя откликнуться на soft-deleted вакансию | vacancy.deleted_at IS NULL | 404 Not Found |
| C4 | Cover letter ≤ 2000 символов | Валидация на уровне Pydantic-схемы | 422 Unprocessable |
| C5 | Отозвать можно только pending-отклик | Статусная проверка | 409 Conflict |
| C6 | Принять/отклонить может только владелец вакансии | vacancy.employer_id == current_user.id | 403 Forbidden |
| C7 | Принять/отклонить можно только pending-отклик | Статусная проверка | 409 Conflict |
| C8 | Только авторизованные пользователи могут создавать отклики | Depends(get_current_user) | 401 Unauthorized |

#### Edge Cases и граничные условия

| ID | Сценарий | Ожидаемое поведение |
|----|----------|---------------------|
| EC-1 | Пользователь отзывает отклик, затем вакансия удаляется | Отозванный отклик остаётся в истории соискателя; ссылка на вакансию ведёт на страницу "Вакансия удалена" |
| EC-2 | Работодатель принимает отклик, вакансия архивируется | Принятый отклик остаётся в статусе `accepted`; отклик виден в истории обеих сторон |
| EC-3 | Два соискателя одновременно откликаются на одну вакансию | Оба отклика создаются (unique constraint на user_id+vacancy_id, разные пользователи — нет конфликта) |
| EC-4 | Соискатель быстро кликает "Откликнуться" дважды | Первый запрос создаёт отклик; второй получает 409 Conflict; UI должен блокировать кнопку после первого клика |
| EC-5 | Работодатель принимает один отклик, остальные pending | Все pending-отклики остаются в pending; работодатель может принять несколько кандидатов |
| EC-6 | Работодатель принимает отклик, соискатель пытается отозвать | 409 Conflict — отклик уже не в статусе `pending` |
| EC-7 | Пользователь удалён из системы (GDPR), но его отклики остались | Отклики анонимизируются: user_id → NULL, applicant_name → "Удалённый пользователь" |
| EC-8 | Cover letter содержит XSS/HTML-теги | Санитизация на бэкенде: все HTML-теги удаляются, остаётся только plain text |
| EC-9 | Пустой cover letter | Допустимо — cover_letter = null; UI показывает "Без сопроводительного письма" |
| EC-10 | Офлайн-отклик (FR-006 пересечение) | Кнопка "Откликнуться" недоступна офлайн с tooltip "Отклики недоступны офлайн"; PUT/POST-запросы не идут через service worker |

**Приоритет:** High  
**Статус:** To Do 📋

## Нефункциональные требования

### NFR-001: Производительность
**Описание:** Система должна отвечать быстро даже при высокой нагрузке.

**Критерии:**
- Время ответа API: < 500ms для 95% запросов
- Время загрузки страницы: < 3s
- Поддержка 1000 одновременных пользователей

**Приоритет:** High  
**Статус:** To Be Tested 🧪

---

### NFR-002: Безопасность
**Описание:** Система должна защищать данные пользователей.

**Критерии:**
- Все пароли хэшируются (bcrypt)
- Все коммуникации по HTTPS
- Защита от SQL injection, XSS, CSRF
- JWT tokens с expiration

**Приоритет:** Critical  
**Статус:** Implemented ✅

---

### NFR-003: Масштабируемость
**Описание:** Система должна легко масштабироваться.

**Критерии:**
- Горизонтальное масштабирование backend
- Read replicas для PostgreSQL
- Redis Cluster для кэша

**Приоритет:** Medium  
**Статус:** Designed 📐

---

### NFR-004: Доступность
**Описание:** Система должна быть доступна 99.9% времени.

**Критерии:**
- Health checks для всех сервисов
- Автоматический restart при падении
- Backup и recovery план

**Приоритет:** High  
**Статус:** Partially Implemented 🔄
