# ADR-003: Геоданные через PostGIS + Nominatim + OSRM

**Статус:** Принято  
**Дата:** 2026-07-22  
**Контекст:** Сервис поиска работы требует геопозиционирования — поиск вакансий рядом, отображение на карте, расчёт расстояний.

## Решение

### Компоненты
1. **PostgreSQL + PostGIS** — хранение координат (тип `GEOGRAPHY(Point, 4326)`), пространственные индексы (GIST), расчёт расстояний на уровне БД
2. **Nominatim** — геокодинг (адрес → координаты) и обратное геокодинг (координаты → адрес). Развёрнут как Docker-контейнер на VPS
3. **OSRM (Open Source Routing Machine)** — построение маршрутов и расчёт времени/дистанции. Развёрнут как Docker-контейнер на VPS

### Backend
- Эндпоинт поиска вакансий по радиусу: `GET /api/v1/vacancies/nearby?lat=...&lng=...&radius_km=...`
- При создании вакансии — опциональный геокодинг адреса через Nominatim → сохранение координат
- Фильтрация и сортировка по расстоянию через SQL с PostGIS (`ST_DWithin`, `ST_Distance`)

### Почему не внешние API
- Google Maps / Yandex Maps — платные, требуется ключ API
- OpenStreetMap + Nominatim + OSRM — бесплатно, полный контроль, работают офлайн
- Внутренние сервисы (Docker) — нет лимитов запросов

### Альтернативы
- **GeoDjango** — rejected: стек уже на FastAPI, не Django
- **Elasticsearch + geo** — rejected: избыточно для MVP, PostGIS покрывает потребности
- **Внешнее API (Google/Yandex)** — отложено: дорого, нет контроля

## Последствия
- Полностью бесплатное гео-решение
- Nominatim и OSRM — тяжёлые контейнеры (~5-10 GB RAM каждый), но на VPS достаточно
- PostGIS запросы быстрые при правильных индексах
- Возможность добавить офлайн-карты через MapLibre на фронте
